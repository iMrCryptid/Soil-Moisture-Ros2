For this task, I chose to simulate soil moisture data as the data is directly related to the science module in the CAD assignment. The publisher represents a capacitive based soil moisture sensor reading from a 12 bit ADC. Each message is of type SoilMoisture. This includes a header with a timestamp, a sensor ID, ADC value and a percentage of moisture calculated using two calibration points (open air ADC value and water ADC value). This is how a real sensor would be calibrated. The simulated data gradually changes with some noise and occasional sudden jumps to represent the probe being forced into a new patch of soil. 

This data would be useful on the rover for the science module of the sensing. When the arm puts the probe into the soil, the Science Module could publish data like this. Any other node (data logger, ground station interface or autonomy node to decide where to sample next) could subscribe. This means there is no knowledge of the sensor hardware needed. In my subscriber code I have included a basic example. The data is categorized into three levels: DRY, OK or SATURATED. To give the operators a more reliable value, a running average is kept. The raw data is also included so it could be re-calibrated. The timestamp and sensor ID helps differentiate between data from different sampling locations or multiple probes.
