For this task I chose to send simulated soil moisture data, since it connects directly to the science module I worked on in the first assignment. The publisher acts like a capacitive soil moisture sensor read by a 12 bit ADC. Each message is a custom SoilMoisture type that carries a timestamped header, a sensor ID, the raw ADC value, and a calibrated moisture percentage. The percentage is calculated from two calibration points (the raw reading in open air and the raw reading in water), which is how the real sensor would need to be calibrated. The simulated value drifts slowly, has a small amount of noise, and occasionally jumps to a new value as if the probe were pushed into a different patch of soil.

On the rover, this data would support the sensing side of the science mission. When the arm places the probe into the ground, the science module could publish readings like these, and any other node (a data logger, the ground station interface, or an autonomy node choosing where to sample next) could subscribe without needing to know anything about the sensor hardware. My subscriber shows a simple version of that: it labels each reading as DRY, OK, or SATURATED and keeps a running average so operators get a steadier value than a single noisy sample. Keeping the raw value alongside the percentage means the data can be recalibrated later, and the timestamp and sensor ID allow readings from different sample sites or multiple probes to be told apart.
